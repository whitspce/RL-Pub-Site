02 / Home OBS

Stream from your phone to OBS at home

Send your camera feed to a home computer running OBS Studio. Use OBS for scenes, overlays and your final broadcast, with scene and broadcast controls on your phone.

Set up scenes, overlays, alerts and other video sources in OBS on your home computer. Roam sends the phone's camera and microphone to OBS, and lets you switch scenes and start or stop the OBS broadcast while you are out.

Your computer handles the extra work of combining those sources and producing the final stream for your platform. The phone still processes and uploads its own camera feed.

This guide uses Tailscale to make a private connection between your phone and home computer, including when you are on mobile data. It keeps the OBS controls off the public internet and avoids router port forwarding. Other private-network setups can work too.

There are three separate connections:

ConnectionWhat it doesWhere you configure it
Roam to OBS, using SRTSends phone video and audioRoam Settings > Stream and an OBS Media Source
Roam to OBS WebSocketControls scenes and OBS broadcastingRoam Settings > OBS
OBS to your platformSends the finished programme to viewersOBS Settings > Stream

Connecting Roam's OBS controls does not send camera video. Receiving the phone feed does not start an OBS broadcast while automatic streaming sync is off.

Before you start

  • An Android phone with Roam Live and working camera and microphone permissions.
  • A home computer with OBS Studio, version 28 or later. Keep it awake with OBS open. Ethernet is preferable for its connection to your router.
  • Tailscale on both devices, signed in to the same private network. Tailscale is a separate service with its own sign-in.
  • Time to test locally before starting a public broadcast.

For the first test, disconnect another VPN on the phone or computer if you use one. Android normally permits one active VPN, and other computer VPNs can interfere with Tailscale. With no exit node selected, Tailscale carries traffic between your Tailscale devices; ordinary browsing uses your normal internet connection. Tailscale's VPN guidance explains the limitations.

No router port forwarding is needed. Keep OBS control port 4455 and SRT port 1234 private. Do not expose OBS through Tailscale Funnel. If you created those router forwards for an older Roam guide, remove them before using this setup. You do not need a separate media server for this route.

1. Connect phone and computer with Tailscale

1A. On your phone

  1. Install Tailscale from Google Play.
  2. Open Tailscale, select Get Started and approve Android's VPN connection request.
  3. Sign up or sign in using Google or another provider offered in the app. Finish any browser approval, then return to Tailscale. Use this same account on your computer in the next section.
  4. Check that Tailscale says it is connected. Leave Exit node at None if that option is shown.

For more help, see the official Android steps.

1B. On your computer

  1. Install Tailscale using its instructions for Windows, macOS, or Linux.
  2. Sign in with the same account you used on the phone and finish the connection steps for your system.
  3. Check that Tailscale is connected. Leave Exit node at None if that option is shown.
Linux tip: connect from the terminal

There may be no app-menu icon. After installation, open a terminal:

tailscale version
sudo tailscale up --timeout=5m
tailscale ip -4

The first command confirms installation. The second connects Tailscale and prints a browser sign-in address when needed. If sudo asks for a password, use your computer login password; typed characters are hidden. The last command shows the computer's Tailscale IPv4 address.

The connection command has a five-minute timeout here so it will not wait indefinitely. If it gives no sign-in address, press Ctrl+C, check whether another VPN is still connected, and retry after ordinary browsing works.

1C. Confirm the connection

Find the computer's Tailscale IPv4 address in Tailscale on either device. It starts with 100.. In the examples below, replace <PC_TAILSCALE_IP> with that address, without the brackets. Use the computer's address, not the phone's.

Confirm both devices are connected and an ordinary website still loads on each. A device appearing in the list is not enough if it is currently offline.

2. Add the phone source in OBS

Keep OBS broadcasting stopped for setup. Its main control should say Start Streaming. In Roam, keep Settings > OBS > Sync OBS streaming with Roam off.

Make a unique SRT passphrase with 20 to 79 random letters and numbers. Save it privately. Letters and numbers avoid URL-escaping problems. Replace <SRT_PASSPHRASE> below with this same value in both apps.

In OBS:

  1. Create a scene called Phone. For the first test, turn Studio Mode off so there is one main preview.
  2. In Sources, select + > Media Source. Create one called Roam phone.
  3. Uncheck Local File and enter this in Input: 
    srt://<PC_TAILSCALE_IP>:1234?mode=listener&passphrase=<SRT_PASSPHRASE>&pbkeylen=32&latency=2000000
  4. Enter mpegts in Input Format.
  5. Set Reconnect Delay to 1 second, if available.
  6. Turn Restart playback when source becomes active off and leave Close file when inactive off. Leave network buffering and other decoder settings at their defaults for the first test.
  7. Select OK, then confirm the source's eye icon is on in the Sources list.

OBS now waits for the phone. A blank picture before Roam starts is expected. OBS documents this SRT receiver method.

The two source options help keep the connection running when you change scenes. OBS otherwise can stop or restart playback as a source becomes inactive or active. Test this on your setup before relying on scene changes. See Media Source properties.

3. Enter the matching destination in Roam

While Roam is stopped, open Settings > Stream and enter this Stream URL:

srt://<PC_TAILSCALE_IP>:1234/live?passphrase=<SRT_PASSPHRASE>&pbkeylen=256&latency=2000

Use the same computer address and passphrase as OBS. Keep the complete URL on one line and check that Roam shows no validation error. Save current URL optionally stores it as a named destination for later use.

Use the correct URL in each app. Roam initiates the connection; OBS waits for it. These examples express the same encryption and two-second SRT buffer using different parameter units. Keep the numbers as shown. The buffer helps absorb network variation, so OBS will show the phone with some delay.

Under Settings > Video quality, choose Data saver for the first connection test and leave Auto bitrate on. You can test Recommended after the basic path works.

4. Check picture and sound without broadcasting

  1. Keep the Phone scene selected in OBS.
  2. Hold Go Live in Roam. With Sync OBS streaming with Roam off, this sends the phone feed to OBS without starting an OBS broadcast. Wait for moving video to appear in OBS.
  3. Speak and move in front of the phone. Check that the Roam phone audio meter moves in OBS and its speaker/mute control is not muted.
  4. Confirm the OBS button still says Start Streaming. This means OBS is not broadcasting to your platform. Keep it stopped for this test.
  5. Use Start Recording on the computer for a short local recording. Stop recording and play the saved file to check the actual picture and sound.
  6. Stop Roam. Wait a few seconds, then start it again and confirm OBS receives a new moving picture. A quick restart can fail while OBS is reopening its receiver; the reconnect-delay setting reduces that wait.

If the image is the wrong size, right-click the source and choose Transform > Fit to Screen. Sources higher in the list can cover sources below them. OBS's overview explains source placement and Studio Mode.

The computer may not play the incoming audio through its speakers by default. Audio monitoring is separate from the sound sent to a recording or broadcast. Use recording playback to check the result before changing monitoring settings. See the OBS Audio Mixer guide.

5. Add remote scene controls

This step is optional for receiving picture and sound.

  1. In OBS, open Tools > WebSocket Server Settings. Some versions label it obs-websocket Settings.
  2. Enable the server and authentication. Keep port 4455.
  3. Generate a password and save it privately. Use a different password from the SRT passphrase.
  4. In Roam's Settings > OBS, enter the values below.
FieldValue
Host (LAN IP or hostname)The computer's Tailscale IPv4 address only
Port4455
Password (required)The OBS WebSocket password
  1. Press Connect and wait for Connected.
  2. Turn on Show OBS control on main screen. This is off by default.
  3. Return to the camera view and open the OBS control. Select a scene and confirm OBS changes its programme output.

OBS WebSocket is built into OBS 28 and later; you do not need to install a separate plugin. OBS's Remote Control guide covers the server settings and recommends keeping authentication enabled with a password.

Reuse your phone source and set up BRB

When another scene needs the phone, choose Media Source > Add Existing > Roam phone. Reuse this one source instead of creating another receiver on port 1234. Switch away and back while receiving to check continuity.

Make an OBS scene for your break screen. If you keep the phone source running behind a full-screen BRB image, covering its picture does not mute its audio. In Roam Settings > OBS, select the exact BRB scene in OBS and leave Mute mic and camera during OBS BRB on.

Test BRB while making a local OBS recording. Confirm the recording shows the break screen, contains no phone microphone audio during the break, and restores picture and sound when you return. Check other OBS microphones and sources separately; Roam's protection applies to its phone feed.

6. Try mobile data before leaving home

Stop Roam, turn the phone's Wi-Fi off, and confirm mobile data works. Open Tailscale and confirm it is connected with no exit node selected. Then repeat the picture, sound, scene-change and stop/restart checks above.

Run a short recording first, then a longer test resembling your intended stream. Watch for freezes, sound drifting out of sync, reconnects and phone heat. A successful connection on home Wi-Fi does not establish mobile coverage or sustained upload capacity.

7. Set up the broadcast from OBS

Your platform details belong in OBS > Settings > Stream for this route. Keep Roam's SRT URL pointing to your home computer.

Choose your platform under Service. Connect your account if OBS offers it, or enter the Server address and Stream Key supplied by that platform in their separate fields. Choose Custom only when your service requires it. A complete phone destination URL with a key appended does not belong in OBS's Server field.

When the incoming picture and sound are ready, use Start Streaming in OBS. Check the platform's own preview and live status. To finish, stop the OBS broadcast and stop Roam. If OBS is recording, stop that separately too.

Optional: test Twitch without live viewing

Before testing remote OBS Start, verify the output using Twitch's bandwidth-test mode:

  1. In OBS, duplicate your profile and name the copy Twitch Bandwidth Test.
  2. Select Twitch under Settings > Stream. If connected by account, enable Bandwidth Test Mode. If entering a stream key manually, append ?bandwidthtest=true to the key in the Stream Key field: 
    <TWITCH_STREAM_KEY>?bandwidthtest=true
  3. Open Twitch Inspector, start OBS streaming, and check that Inspector receives the test. Check your public channel in a signed-out browser too; if it is live, stop OBS and correct the test setup.
  4. Stop OBS when finished. Switch back to your normal profile before an intended broadcast.

Twitch documents that the bandwidth-test parameter disables live viewing. It is a Twitch-specific option, not a general private mode for other services.

Optional: start and stop the OBS broadcast from Roam

The OBS drawer has Hold to start OBS broadcast and Stop OBS broadcast. They start and stop the platform output configured in OBS, even if Roam is not sending a phone feed. They do not control OBS recording. OBS can separately be configured to record automatically when streaming.

Roam 0.10.5: disabling Android animations can make OBS Start trigger before a full hold. Use the computer for your first output test, and treat the phone's Start action as capable of broadcasting as soon as you press it.

Leave Sync OBS streaming with Roam off to control the two outputs separately. Enabling it asks OBS to start when you start the phone stream; it does not wait for you to approve the received picture. Roam automatically stops only broadcasts it started through that sync option.

Optional: stream to several platforms

Once the phone feed and your first OBS destination work, you can send the finished OBS broadcast to more platforms. Keep Roam's SRT URL pointing to your home computer.

Send OBS to a restreaming service

This keeps one outgoing upload from your home computer. The service distributes it to your platforms. See the free service options and their limits.

For Restream, connect your platform accounts and enable the channels you want. In OBS Settings > Stream, choose Restream.io > Connect Account, or use the stream key Restream supplies. Follow Restream's OBS setup. Roam's OBS controls start and stop this main OBS output; check each platform's live status as well.

Send OBS directly to each platform with a free plugin

Multiple RTMP outputs adds more destinations to OBS. Each one uses a separate upload from your home connection. Make sure it can sustain the total bitrate, with room for other traffic. Your phone still uploads just one feed.

  1. Stop broadcasting and close OBS. Install the plugin from its official releases, choosing a build for your operating system, OBS version and installation type. Reopen OBS. The OBS version needed by a plugin can be newer than the version needed for this guide.
  2. Keep your first platform configured in OBS Settings > Stream. Open Docks > Multiple output and choose Add new target for another platform.
  3. Name the target, then enter that platform's server address and stream key in their separate fields.
  4. For both video and audio, choose Reuse the streaming encoder as OBS if the platforms accept the same settings. This saves encoding work on the computer. Each destination still needs its own upload.
  5. Enable both Sync start with OBS and Sync stop with OBS for the target to follow the main OBS broadcast. Save it. Repeat for any other platforms.
  6. While still at the computer, start the phone feed and the main OBS broadcast. Check picture, sound and live status on every platform. Stop the main broadcast and confirm every destination stops.
  7. Before relying on the setup away from home, repeat start and stop using Roam's OBS controls, and check all destinations again.

The sync settings matter. They are off for new plugin targets. Roam controls the main OBS output and cannot show whether each extra destination is live. Check the plugin and platform dashboards during setup. These extra outputs are real broadcasts; the earlier Twitch bandwidth-test setting applies only to the destination where you configured it.

Troubleshooting

OBS controls connect, but video is blank

Check the two SRT URLs, matching SRT passphrase, mpegts input format, and active source. A working control connection does not test the video connection. Check the source eye, scene selection and sources covering the image. In Studio Mode, the programme shown to viewers is on the right; the left side is a separate preview.

The OBS control is missing from Roam

Enable Settings > OBS > Show OBS control on main screen. Hiding this control does not disconnect OBS or turn off automatic streaming sync.

OBS says Connecting or cannot connect

Confirm Tailscale is actually connected on both devices, OBS is open, and the computer is awake. Check the computer address, port 4455, password and enabled authentication. Enter only the address in Host, without http://, ws://, a port or a path.

The source stops during scene changes

Reuse one existing phone source. Check that both Restart playback when source becomes active and Close file when inactive are off. Test switching away and back. Keep the initial test simple before adding complex scene collections.

The audio meter moves, but the recording is silent

Check that the phone source is unmuted in OBS and assigned to the audio track used by your output. In OBS versions with Monitor Only (mute output), that option excludes sound from the normal output. Avoid capturing the same sound again through Desktop Audio or a second microphone; duplicated paths can cause echo.

Mobile data is choppy

Try Data saver and Auto bitrate. Confirm the home computer's connection is healthy. Tailscale may use a relay when a direct connection is unavailable; being connected does not guarantee enough capacity for a steady video stream. Retest before increasing quality.

The feed and ordinary internet stop working

Stop Roam and OBS, then check ordinary internet access on both devices. Use Ethernet for the home computer where possible. Repeat a short test with the phone on mobile data and Tailscale connected before increasing quality or trying a longer stream.

A firewall or private-network policy blocks the connection

The receiver needs UDP 1234 and the controls need TCP 4455 between these two devices over Tailscale. Check the computer's incoming-connection settings and any Tailscale access policy. Keep any exception limited to this private connection. Do not disable the firewall or create public router forwards. Tailscale's connection troubleshooting covers device reachability; operating-system firewall steps differ.

Tailscale is disconnected and the phone loses internet

Check whether Android's Always-on VPN or Block connections without VPN is requiring a VPN that is not connected. This setup does not require VPN lockdown or an exit node. Reconnect Tailscale and confirm ordinary browsing before retrying.

If you need help, report the step that failed, Roam version, phone model, computer operating system and OBS version. Redact passwords, full stream URLs and account details from screenshots or logs before sharing them.
